## VLA面临的问题

借鉴多模态的思路，pi_0，OpenVLA 等传统 VLA 模型先用 VLM 融合各类模态，端到端模仿学习。VLM 虽然也在视频上进行训练，但以对齐视频-文本信息为目标，语义理解能力较强，而空间理解能力有限，并非一个完美的**机器人策略** backbone。

![](./Pasted%20image%2020260223200023.png)
而视频模型在视频预测任务上训练，具有更好的空间和物理知识。本文的 Video Action Model 是以视频模型为 backbone 的一系列 VLA。

## 发展路线
### 视频规划 -> 提取动作
代表：Video Policy (Toyota Research Institute, 2508.00795), mimic-video (MSFT, ETH Zurich, UCB, 2512.15692)

mimic-video 先用冻结或微调的视频生成DiT，视频只进行部分去噪，逆动力学 DiT (IDM) 以**部分去噪的视频** + 本体状态为条件，并对视频 DiT 进行 cross-attention，恢复出低层机器人控制指令。

![](./Pasted%20image%2020260223213610.png)
Video Policy: video U-Net输入多模态信息，每个去噪步提取隐藏层特征，输入 action U-Net 回归为动作

### 多模态联合预测

代表：Unified World Models (Toyota Research Institute, 2504.02792), Cosmos Policy (NVIDIA, 2601.16163), LDA-1B (PKU, 2602.12215v1)
![](./Pasted%20image%2020260223195546.png)
为了提高推理速度，同时进一步对齐多模态信号，将动作、视频放在同一个序列中预测。Cosmos Policy提出一种极简的联合预测方案，对视频模型的架构**不做任何改动**。机器人动作、本体感受状态、累计奖励全部编码为视频模型的 token，通过单一的流匹配目标，让模型同时预测上述模态。

LingBot-VA论文中比较了Co-training（联合预测）与VGM+动作头策略的区别。在Robotwin2.0 Easy 中使用 Pretrained LingBot-VA / Wan2.2-5B+动作头，经过相同后训练（3k步）的平均成功率 92.9% / 80.6%，在更长任务下差距更大。（不过这个比较不算公平，两个模型可能注意力机制/观测/训练量不同）

### 自回归闭环生成

代表：LingBot-VA (Robbyant, 2601.21998v1), DreamZero (NVIDIA, 2602.15922)

之前的架构都采用**全局同步**去噪，即一次生成全部视频 + 完整动作。在采取联合预测的基础上，此类模型采用流式生成和因果注意力，将模型完全改为自回归架构

![](./Pasted%20image%2020260223220545.png)

以LingBot-VA为例：
- 输入：视觉用 Wan-VAE (因果“注意力”) tokenize​；动作向量经 MLP 投影成 token embedding，与视觉 token 对齐到同一序列
- 使用双流 DiT 分别处理视频、动作信息
- 每层里 video/action 先各自进行注意力，再进行交叉注意力
- 采取类似 Diffusion Forcing 的方法，训练时视频随机添加噪声，推理时视频只去噪至 $s=0.5$，保证生成质量和速度

对于不同时间长度（尤其是长程）的任务，自回归架构具有更强适应性：

1. 将之前的观测视频作为条件，增强记忆，同时避免误差积累。在考验记忆的任务（擦拭盘子6次、搜索两个盒子中的五块饼干）中，LingBot-VA成功率100%，pi_0.5成功率50%
2. 视频 chunk 可以利用KV Cache，一定程度上加快了生成速度

DreamZero 中相对公平地比较了 AR 和双向架构，任务进展相似情况下，AR 生成的运动更平滑，且推理速度提升3-4倍。
需要注意的是，DreamZero 和 LingBot-VA 都用的是 Wan 作为 backbone，Wan 自身实际上是非因果注意力的。

## 最新模型概览

*来自2512~2602的工作*

### LingBot-VA: 推理-执行异步

![](./Pasted%20image%2020260224091716.png)

- Sync Paradigm: 模型生成时机器人闲置，机器人执行时模型闲置；
- Async Paradigm: 利用视频生成模型**预测未来**的能力，可以用**预测的观测**暂时代替实际观测，让模型始终处于运行状态；
- Naive Async: 只使用预测观测，容易导致开环漂移，即预测没有修正，误差逐渐累积；
- FDM-grounded Async: 学习一个FDM模块，预测 $z_{t+1}:z_{t+K}$ 视觉状态作为暂时的Cache，然后主模型预测 $t+K+1:t+2K$ 的视觉和动作。
![](./Pasted%20image%2020260224083140.png)

相比串行方法，取得相近的成功率，但任务完成速度快了2倍。
### DreamZero: 推理加速、zero-shot、长尾数据

![](./Pasted%20image%2020260224103726.png)
模型加速方面，DreamZero 基于 Wan2.1-14B，为了达到理想控制频率，使用 CFG 并行计算、NVFP4 混合精度量化进行系统加速。为进一步提速，提出 DreamZero-Flash 噪声调度：
![](./Pasted%20image%2020260224102427.png)
训练时强制视频的噪声时间步服从 Beta(7,1) 的偏态分布，而动作时间步保持均匀分布，即要求模型从视频生成的早期即重建出动作。实现了38倍推理加速，达到 7Hz 高频闭环控制。

数据策略方面，DreamZero 强调避免一般数据集中**同一任务重复演示**。在 AgiBot G1 上收集 500 小时数据，覆盖了 22 个现实场景，单集平均长达 4.4 分钟，并包含 42 个子任务。

DreamZero展现出更强的 **zero-shot** 能力。在**没有动作标签**的**12 分钟**人类视频下训练，仅进行视频预测监督，即可将未见任务成功率提升42%；使用新机器人**随意操作**的视频训练，即可适应新机体。

### Cosmos policy: 极简统一架构

以Wan2.1作为backbone，但同时将Proprio, Action chunk, Value等额外模态均作为 latent frames 插入原视频序列中。

在训练时同时学三类目标：Policy ( $p(a,s′,V(s′)∣s)$ ) , World model ( $p(s′,V(s′)∣s,a)$ ) , Value function ( $p(V(s′)\mid s, a, s′)$ )，对不同目标不改动网络，只改动训练数据、损失函数等。对奖励信号的预测让模型具有一定规划能力，弥补视频生成模型的不足。

### LDA-1B: VLM+DINO Backbone，异构数据

![](./Pasted%20image%2020260225154842.png)
和其他VA不同，**不使用VGM**为Backbone，意在避免低效的像素级计算，同时又可以使用多样异构的数据。

- 输入：观测、语言、时间步、Task Embedding (Forward Dynamics, Inverse Dynamics, Policy, Visual Planning共四种)；
- 视觉信息使用DINOv3压缩，Action Chunk随机初始化，在一个从头训练的MM DiT中去噪，输出Action Chunk和DINO（代表预测观测的DINO特征）；
- 预训练：**冻结VLM和DINO**，只训练MM DiT。对于缺失某模态的数据，用可学习的“模态占位符”（Register Tokens）占位。
- 对于不同的 Task Embedding 采取不同损失函数。（1）Policy: 输入当前图像语言，仅计算 action 损失；（2）Forward Dynamics: 输入当前图像+动作，计算 DINO 特征重建损失；（3）Inverse Dynamics: 输入当前图像语言+未来图像，计算action损失；（4）Visual Forecasting: 输入当前图像语言，计算DINO损失。

使用非常多样的第一人称数据，超过30k小时，包含机器人真机（8k），机器人仿真（8k），人类+动作标注（7k），人类无动作标注（10k）。由于应用了Register Tokens和Task Embedding，对于异构数据无需修改网络结构。

### Motus (2512.13030): MoT、光流提取动作

![](./Pasted%20image%2020260224210043.png)

Motus 使用三个并行的 backbone: VLM (Qwen2-VL), VGM (Wan 2.2 5B), Action Expert (DiT，从头训练)。三者处理不同输入，但使用特殊的注意力层共享token。借鉴 UniDiffuser，给视频/动作分配不同噪声水平和时间步，同一模型可灵活切换 VLA/世界模型模式，保持 VLM 的语义推理能力。

![](./Pasted%20image%2020260224210152.png)

**训练数据**方面，利用大量无标签数据，提取隐动作训练。

1. 输入视频帧，转为 2D 光流场，自编码器编码为 4 个 512 维 token，最后经过一个轻量编码器转换成 14 维隐动作（和动作token形状相同，便于对齐损失函数）。
2. 训练自编码器：90%数据为人类 Ego 视频，以重建光流为目标；另有10%含动作标签的机器人轨迹，以重建动作为目标，使其分布靠近机器人控制信号。
3. 在上图 Stage 2 的训练中，将 Latent Action 作为人类视频的动作标签。

完整训练管线如上图，Stage 1 用人类 Ego 数据+机器人数据无监督训练 VGM，Stage 2 用人类+机器人数据（带动作标签）同时进行模仿学习和视频预测训练，最后针对目标机型微调。

不同论文中使用的基准不尽相同，只能大概比较。

### DreamDojo (NVIDIA, 2602.06949): 动作条件世界模型

不是 video action model，但作为同期类似工作简单提及。

和LingBot-VA、DreamZero不同，是一个**以动作为条件**的世界模型，给定当前画面+Latent Action，预测未来画面。该模型**不接受语言输入**，**不预测动作**，必须配合 Policy (如 VLA) / Value Model 才能用于真机。

1. 训练一个 latent action model，由前后两帧 RGB 编码隐动作。Encoder: 输入两帧画面，输出32维连续向量，代表动作；Decoder: 输入前一帧+Latent Action，重建后一帧
2. 以 VGM (Cosmos-Predict2.5) 为backbone，将动作信息作为条件，预测未来视频。（预训练时使用 LAM 提取的 Latent Action，微调时使用真机连续动作转换成的 Action）
3. 训练时，除基础的 Flow Matching Loss，还引入时间一致性损失 (Temporal Consistency Loss)，计算模型预测的“速度” $(z^{i+1}-z^{i})$ 与真实视频“速度” $(v^{i+1}-v^{i})$ 的 MSE。

实际使用：
1. Policy Evaluation: 配合Policy Model (输入画面，输出动作)，在虚拟操作视频中评估策略成功率。实验证明机器人在 DreamDojo 里的成功率与真实世界的成功率高度一致（$R^2$ 0.995）。
2. Model-based Planning: 训练一个Value Model。对不同权重的Policy（或提出多个提案的Policy），先在DreamDojo中模拟执行多种提案，再用Value Model评判得分，选择得分高的执行。
3. Live Teleoperation: 充当物理模拟器，人类操作员戴上PICO VR 控制器，以人类动作为Condition生成模拟视频。

## Video Action Model的优缺点

缺点：
- 对System 1，生成速度慢。以DreamZero为例，即使经过量化、部分去噪、其他系统优化，依旧只有7Hz的控制频率，远慢于性能相当的VLA（如X-VLA）。不足以控制人形机器人，也不能反应突然情况。
- 对System 2，推理能力有缺陷。如果不再使用VLM作为backbone，则语义推理、数学推理等能力难以保证。

优点：
- 突破训练数据量瓶颈。视频模型本身经过大量数据训练。VA也天然支持多机型、乃至人类视角数据训练，不再依赖单一机型数据。
- 高泛化性。由于训练数据的多样性，对于新任务/机型，仅使用极少数据即可适应。LingBot-VA和DreamZero均报告了相比pi_0.5更高的样本效率。

## 半年后回顾

本篇文章最早在 26 年 2 月底完成，彼时 WAM 甚至还没有统一的术语，因此本文还使用了 "Video Action Model" 这样的名字。半年过去， WAM 新架构层出不穷，然而 SOTA VLA 却依然基本沿用 pi0.5 的架构，DreamZero 和 LingBot-VA 似乎也很难复现出论文中的精彩故事。

当时刚刚接触具身领域，被论文故事彻底震撼，于是一段时间里沉迷于各类新奇架构，忽视多数工作的 weakness 和真正的问题。如今看来，VLM-based VLA 架构并非一无是处，而 WAM 目前还基本停留在 toy model 阶段，没有真正 scaling 出效果，也就无从正面比较两者。

- 常见的评估不能衡量和区分模型能力。LIBERO 和 RoboTwin 上各个模型都称自己为 SOTA。跨具身泛化、语义理解、场景/任务组合泛化等应该有更强、更普遍使用的基准。
- 机器人策略需要具身原生的模型。VLM 或 VGM 可能都只是最终模型的中间阶段。从这个角度看， Motus 的架构设计其实非常理想，统一语义推理理解和未来预测。
- 架构并不能解决很多问题。多数架构雕花徒增复杂度，有效的方法并非来自复杂度，而是来自直接的 insight。
